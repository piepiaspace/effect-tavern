# Prompt Tree · 设计时请求预览

作者在开局前就能回答两个问题：此刻哪段设定会进入 narrate 请求？改动一个条件或一条 Hat 消息后，交给 SDK 的消息哪里变了？第一条交付路径贯穿 #194 B 与 #210，#211 后续扩展声明式消息时沿用同一视图。

## 作者怎么用

单卡舞台上的 Prompt Tree 只读。作者从工坊或 Hat 编辑器进入沙盒，选择开场，调整字段，试填玩家输入。游玩侧栏入口打开已有故事的分支预览。左侧按装配顺序展开消息、缓存断点与来源片段，点片段可回到拥有它的编辑器。返回时恢复这张卡的预览条件和选中项。工坊与 Hat 编辑器在打开预览前完成普通编辑的保存，成功后按所选资产 ID 预览，失败则留在编辑器。尚未采纳的候选可以在内存中试览。没有当前卡的 Hat 入口需显示所选样例卡。

首版聚焦 narrate 的首次请求。沙盒显示本次采用的状态、事件、交付条目和输入，注明 lookup、decide、direct 尚未执行。作者可点选模型可读条目，试验它进入 `<context>` 的效果。故事模式以所选分支节点之后为起点，读取该路径的状态、驻留和已有摘要，再按当前阶段路由预览下一次装配。若该路径需要新生成摘要，应指明缺少的材料。查看某个节点当时实际发过什么，进入 Inspector。两页共用请求视图。

## 谁负责装配

- **运行时**从 session 的 narrate 路径提取确定性准备逻辑。已知的状态、历史、交付快照及本轮决定构成输入。真实游玩和预览共用片段求值、措辞与 Hat 展开、历史选择和消息拼接规则。沙盒只提供本次试验的材料。CLI 的 `card view` 用于静态卡面检视，保留自己的输入和展示语义。
- **Provider**继续拥有 `wire(format, messages, prefill)`。发送和预览各在自己的路径调用同一转换一次。界面显示装配角色、转换后的 SDK 角色和 prefill 冲突。路由尚未配置时，作者仍可查看装配消息，界面标明连接未选。发生转换错误时保留可定位问题的装配结果。
- **服务端**的只读 `POST /preview` 根据卡与开场或故事与节点选择材料，解析当前阶段生效的 Hat 及连接配置。沙盒支持候选卡与 Hat、字段、事件、输入。候选无效时返回诊断。整个查询在内存求值，零模型调用，零持久化写入。
- **客户端**负责树的展开、筛选、定位和返回。Inspector 读取调用时记录的消息、来源及角色转换信息，旧记录可直接显示已有消息。总览中的编辑链接遵循资产归属，排序在对应编辑器完成。

## 来源与条目

文本拼接时生成消息内的半开区间 `[start, end)`，以 JavaScript 字符串索引切取原文。保留来源资产与条目标识。历史回复可整体归属故事节点，保留原有 parts；摘要标为折叠历史。Inspector 可随调用保存来源区间与发生变化的角色，无需复制消息正文。

覆盖、静默和条件落空由实际作出取舍的代码记录。未填代称是否阻止发送遵循现有展开规则：卡文保留未填的原文并显示诊断，玩家来源因缺词被丢弃时才计入落选。前端直接展示决定与原因。

条目面板按同一资源并列呈现驻留版本、可读目录或章节、开窗和访问权限。一个已驻留的条目仍可有未读章节。试验模型读取时在临时 lookup 上走现有 `read` 逻辑。显式玩家选择按 `input.invoke` 的玩家权限处理。两种操作在预览中注明来源。

## 交付与验收

1. 打通卡片沙盒、narrate 准备、provider 转换和独立页面。用真实 session 入口配测试模型截获首个 narrate 的 SDK 消息，在相同阶段材料和路由下与预览逐项比较正文、角色、parts 和缓存标记。另测 prefill 错误能定位到尾部消息。
2. 用《Life of Pi》的隐藏字段「裂隙」做作者验收。从 2 拨到 3，进入 `<fiction>` 的片段应从 `seam-calm` 切到 `seam-mid`，选中任一片段都能看到触发条件和卡内来源。这个场景在独立页面即可完成。
3. 接入故事分支、Inspector 和编辑器入口。验收同卡两个分支各自的历史及驻留，修改候选后书架修订号保持原值，修改已保存的 Hat 后旧调用仍显示当时的记录。待 #210 源码缓冲可用，再将请求视图嵌在编辑区旁。
