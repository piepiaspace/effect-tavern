输入 `tavern` 查看命令菜单。从源码运行时，在仓库根目录输入 `bun run tavern`。用 `tavern start --help` 查看启动选项。

在安卓手机的 Termux 中安装：

```sh
curl -fsSL https://github.com/piepiaspace/effect-tavern/releases/latest/download/install.sh | sh
```

运行 `tavern start` 启动，`tavern update` 更新。用旧启动器安装过的手机可以重新运行上面的安装命令，故事库保存在 `~/.tavern`。

## 0. 运行酒馆（`start`、`stop`、`status`、`update`、`doctor`）

玩家用的命令，手机（Termux）和电脑上一样。帮助（`tavern --help`、`tavern <命令> --help`）用玩家的语言（中文；`TAVERN_LANG=en` 为英文），按手机终端的 48 列排版。

| 命令 | 做什么 | 退出码 |
| --- | --- | --- |
| `tavern start` | 提供网页和它的接口。服务期间持有设备的唤醒锁（Termux 的 `termux-wake-lock`）；在终端上，等服务有回应后打开网页（`--no-open` 不打开）。同一个库已有酒馆在运行时，第二个 `tavern start` 说出它在哪并以 `0` 退出。端口被占用时不启动，并给出要试的命令；端口不会自己换。 | `0`、`1` |
| `tavern stop` | 经由地址文件和 PID 找到服务这个数据目录的酒馆，停止它并等它退出。开发服务（`vp dev`）留给它自己的终端。 | `0`（没有在运行也是）、`1` |
| `tavern status` | 立即返回、不联网：在不在运行、地址、数据目录、版本。`--json` 为 `{running, url?, pid?, data, version}`。 | 运行中 `0`，没有 `3` |
| `tavern update [--yes] [--check]` | 读发布的 `release.txt`，显示现在与最新的版本和变化，询问（只在终端上），检查剩余空间，把平台的发布文件下载到二进制旁边，要求新文件的 `--version` 回答预期的版本，再改名覆盖正在运行的二进制。任何失败都保留旧的二进制。仍在运行的酒馆要重启后才是新版本。`TAVERN_MIRROR` 指定镜像（https 地址或目录）。从源码运行时拒绝。 | `0`、`1`、`2`（没有终端又没有 `--yes`） |
| `tavern doctor [--verbose]` | 每项一行，`✓`、`!` 或 `✗`，每项一个下一步：设备与平台、命令的位置与版本、数据目录、剩余空间与更新所需、运行中的酒馆和它的端口、到发布页的网络、设备工具、旧启动器留下的文件、`<数据目录>/log/turns.jsonl` 里上次失败的回合。 | `0`、`1`（有 `✗`） |

本地操作被拒绝时，酒馆会说明发生了什么、可能的原因、`>` 标出的一个下一步、什么被原样留下，以及一行原始事实。`--json` 时失败是 stderr 上的一行 `{"error":{"code","message","next"}}`。

服务默认在终端打印每次模型请求和回复。`tavern start --log turn` 显示回合摘要，`--log quiet` 只报告失败。上游错误保留 HTTP 状态和原文，失败请求可在 `<数据目录>/log/turns.jsonl` 查找。

## 1. 离线制卡工具（`card`）

运行 `tavern card <subcommand>`（从源码为 `bun run tavern card <subcommand>`）。所有离线命令均不打开库、不调用在线模型。

```sh
bun run tavern card init my-card --template chat
bun run tavern card check my-card.yaml --json
bun run tavern card view my-card.yaml --stage narrate --state hp=2 --events won
bun run tavern card test my-card.yaml scenario.yaml
```

### `card init <id> [--template chat|readout|rpg|world]`
在当前目录独占创建 `<id>.yaml`（文件已存在则报错）。四种最小脚手架对应两个卡片坐标，不预装多余机制：

| 模板 | `persona` 槽位 | 默认 `input` | 典型场景 |
| --- | --- | --- | --- |
| `chat` | 有 | `act` | 一对一或群像自由对话 |
| `readout` | 有 | `note` | 带状态读数与分段的引导叙事 |
| `rpg` | 无 | `act` | 带动作与掷骰检定的冒险卡 |
| `world` | 无 | `note` | 无玩家主角的大世界推演 |

### `card check <card> [--json]`
依次校验 YAML 语法、`Card` Schema、规则初值、静态 lint 诊断、字段量表绘制规格（`drawn`）、各开场初始状态与开窗预览，以及各分段 Token 估算。存在 `error` 时返回退出码 `1`，仅有 `warn` 返回 `0`。

### `card view <card> [flags]`
渲染指定阶段（`--stage narrate|direct|record|lookup`）在给定状态下的完整请求分段、缓存断点、槽位来源及每条 `Cond` 子句的求值详情：
- `--greeting <n>`：先施加 `greetings[n].do`（从 `0` 起算）；
- `--state <k=v>`：覆盖开场结算后的字段值（可重复传参）；
- `--events <a,b>`：传入本轮事件以预览 `lore` 的 `offer` 开窗；
- `--pin <id>`：模拟玩家本轮主动调用已解锁且 `player: true` 的条目（如 `card:<id>` 或 `pack:<row>/<entry>`）；
- `--persona <text>`：覆盖玩家人设文本；
- `--lore`：同时列出已全部解锁且无未开窗口的 lore 条目。

### `card test <card> [scenario.yaml]`
使用零 Token 确定性 `fake` 模型跑通完整 `Session` 回合断言；省略场景文件时执行单轮冒烟测试。

```yaml
seed: 42 # 首个掷骰使用 seed + 1，后续每次递增 1
greeting: 0
steps:
  - text: 向前走
    replies:
      narrate: ["你走到了门口。"]
      record:
        - notes: 已到门口
          options: []
    expect:
      events: []
      windows: []
      lore: []
      end: end
      products: { notes: 已到门口 }
```

## 2. 展开 SillyTavern 旧卡（`card unroll`）

`tavern card unroll` 按 SillyTavern 自身的提示词装配顺序将 PNG（`ccv3` / `chara` 块）或 V2/V3 JSON 卡片展开为可读文档，只读不写、不调模型：

```sh
bun run tavern card unroll card.png --user 李
bun run tavern card unroll card.json --json
```

展开后的 Markdown 完整保留原作者分段，可直接传给 `tavern card sort` 按段落下标归位。

## 3. CLI 宿主、工坊与故事管理（`tavern`）

在仓库根目录运行 `bun run tavern <subcommand>`（`packages/server/bin/tavern.ts`）：

- **自动找库（默认）：** 数据目录依次取 `--data`、`TAVERN_DATA`（旧名 `DATA`），都没有时编译出的二进制用 `~/.tavern`，从源码运行用 `./.tavern`；根目录的 `bun run tavern` 脚本设了 `TAVERN_DATA=.dev`，即开发服务的库。若运行中的 `tavern start` 或 `vp run dev` 占着这个库，它已在锁文件旁写下地址（`tavern.db.address`），命令就经由它（HTTP/SSE）执行，并在 stderr 说明；没有人占着时，命令自己打开 `<数据目录>/tavern.db`，在本进程里用同一个处理函数回答自己的请求。占着库的进程约 2 秒内都没写出地址，退出码 3 并写出它的 PID；设了 `MODEL=fake` 却找到用真实模型的酒馆，也是退出码 3。绝不静默切库。
- **另一台机器（`--server`）：** 传入 `--server http://192.168.1.20:7777`（或设 `TAVERN_SERVER`）即可通过 HTTP/SSE 连接那台机器上的酒馆，不读任何本地文件。
- **任意位置：** `--json`、`--data <目录>`、`--server <地址>`、`-h/--help`、`-V/--version`。退出码：`0` 完成，`1` 被拒绝或失败，`2` 命令行写错，`3` 库无法访问。

```sh
# 书架：新库里没有卡片。从文件安装、列出、导出、移除
bun run tavern card install ./my-card.yaml     # 已有同 id 的卡时覆盖它
bun run tavern card install https://example.com/cards/my-card.yaml   # 单张卡自己的链接
bun run tavern card list
bun run tavern card export my-card -o my-card.yaml
bun run tavern card remove my-card             # 这张卡还有故事时拒绝

# 卡库：可选的取卡来源（含 index.json 的目录或 https 地址）
bun run tavern depot add https://example.com/cards/
bun run tavern depot add ./my-cards            # 目录仅限本地直连模式
bun run tavern depot list
bun run tavern depot show <卡库 id>            # 卡库里的卡，以及各自在书架上的状态
bun run tavern depot pull <卡库 id> <卡片 id>  # 复制一张到书架；更新时加 --replace
bun run tavern depot remove <卡库 id>          # 已取的卡片保留

# 工坊三件套
bun run tavern card compile ./my-card.yaml --select fiction.setting --intent "交情达到 8 时开启信件第 2 层" -o candidate.yaml
bun run tavern card sort ./my-card.yaml ./notes.md -o candidate.yaml
bun run tavern card review ./my-card.yaml --json

# 故事生命周期管理
bun run tavern story list --json
bun run tavern story new my-card
bun run tavern story show 1
bun run tavern story export 1 --format md > story.md
bun run tavern story remove 1

# 启动服务（--headless 只提供 API）与编译二进制（bin/tavern.ts，内含构建好的页面）
MODEL=fake bun run tavern start --headless --port 7777
cd packages/server && bun run compile && ./dist/tavern --version
```

## 4. 终端交互与管道游玩（`tavern play`）

纯数字参数表示续玩已有故事 ID，其余参数作为已安装卡片的 ID 新建故事（数字卡片名可加 `--card` 强制新建）。支持交互式行输入、`--input` 单步执行、stdin 管道、`--user <name>`（写入该卡上的玩家名 `{{user}}` 并对该卡后续新局生效）以及 `--jsonl` 事件流输出：

```sh
MODEL=fake bun run tavern play my-card --greeting 1 --set bond=3 --user "陆沉" --note "雨夜初见"
```

| 斜杠命令 | 行为 |
| --- | --- |
| `/greet [index]` | 选择开场白开启新根（默认 `0`） |
| `/act <text>` / `/note <text>` | 显式走角色行动（`act`）或场外指导（`note`）通道 |
| `/pin <resource-id>` | 本轮主动调用上下文条目（如 `card:guide`、`pack:p/entry`） |
| `/set <field=value>` | 修改当前节点字段值（`setField`） |
| `/swipe [node]` / `/reword [note]` | 从 `lookup` 重跑或从 `narrate` 重写当前正文 |
| `/checkout <node\|root>` | 切换分支到目标版本最新叶节点，或回到空根 |
| `/tree` / `/context` / `/detail [node]` | 查看节点树 JSON、当前 `WorldState` 或单轮结算变更详情 |
| `/inspect [node]` | 查看该轮各阶段模型调用记录（遵守服务端 `inspect` 开关） |
| `/attach` / `/stop` / `/quit` | 接管运行中回合、中断当前生成或等待队列完成后退出 |
